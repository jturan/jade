# jade

**J**ason's **A**gentic **D**evelopment **E**nvironment — a CLI for orchestrating
AI coding agents from idea to merged pull request.

> Status: early. The scaffold and environment checks work; the pipeline commands
> are being built. See the [issues](https://github.com/jturan/jade/issues).

## What it does

jade drives a pipeline:

```
discovery  →  plan  →  [YOU APPROVE]  →  issues  →  build loop  →  [YOU APPROVE]  →  merge
```

- **Discovery** is a conversation with an agent that ends in a scoped note. It is
  allowed to be terminal — exploring an idea and dropping it is a success.
- **Planning** turns that note into one sectioned plan (outcomes and acceptance
  criteria; approach, architecture and risks) and proposes a breakdown into units
  of work, each with a model, an effort level, and review flags.
- **The build loop** dispatches builder and reviewer agents into herdr panes,
  one unit at a time, retrying bounded failures and escalating the rest.

## Design decisions

**GitHub is the state store.** Each unit of work is an issue whose body carries
the unit plan plus a YAML block of model/effort/review settings. Labels carry
status. A tracking issue carries the sequence.

This keeps the orchestrator thin and re-derivable — it reads state, decides the
next action, dispatches, and forgets. Nothing important lives in an agent's
context, so the loop survives compaction, restarts, and moving between machines.
You can stop work on one laptop and resume on another.

**Two human gates, and only two.** You approve the plan before any code is
written, and you approve every merge. Everything in between runs unattended.

**Agents run in herdr panes, not in-process.** Dispatch is vendor-neutral, so a
Codex reviewer can sit beside a Claude builder, and you can watch any agent work.

**Prompts are data, not code.** Templates are embedded in the binary so it stays
self-contained, and overridable from `~/.config/jade/prompts/` so tuning a prompt
never requires a rebuild.

**Nothing personal is compiled in.** Vault paths, repo roots, and profiles live
in `~/.config/jade/config.yml`, generated by `jade init` and never committed.

### Role defaults

Pay for thinking, economize on execution, never cheap out on security review.

| Role | Model | Effort |
|---|---|---|
| Discovery | Opus | high |
| Planning | Opus | high |
| Orchestrator | Sonnet | medium |
| Builder | Sonnet | medium |
| Code review | Sonnet | medium (→ Opus/high on large or cross-cutting diffs) |
| Security review | Opus | high |

Any of these can be overridden per unit of work in the issue's YAML block, so the
decision is made once at plan time rather than re-argued at PR time.

### Profiles

A profile describes what differs between machines — which git host is reachable,
which vendors are permitted, and where discovery notes are written. A personal
laptop might write discovery notes to an Obsidian vault; a work laptop writes
them to `docs/discovery/` in the repo instead.

## Requirements

- [herdr](https://herdr.dev) — the multiplexer agents run in
- [`gh`](https://cli.github.com) — authenticated
- At least one agent CLI (`claude`, `codex`)
- Go 1.24+ to build from source

Run `jade doctor` to check all of this on a new machine.

Any Go installation works. [mise](https://mise.jdx.dev) is a good choice if you
work across several machines, since it pins the same version on each of them.

## Install

```sh
go install github.com/jturan/jade@latest
jade doctor
jade init
```
